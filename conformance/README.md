# PaperKnife conformance corpus

Documents, the steps done to them, and what PaperKnife for Windows observes. Every PaperKnife
app runs these cases and must observe the same thing. Each case names the shortcoming it guards
against (see [INDEX.md](INDEX.md)), so a bug fixed in one app can't come back in another.

The corpus is generated by PaperKnife for Windows from the cases in
`tests/PaperKnife.Core.Tests/Conformance/CorpusCases*.cs`, and its tests fail when it is out of
date. The other apps keep a copy of this folder, with the commit it came from in `SOURCE`.

Every test of PaperKnife for Windows whose scenario is a document session has a case with the
same document and steps. A case's id begins with its area: `document-`, `edit-`, `truetype-`,
`pages-`, `permissions-`, `runs-` (lines drawn letter by letter), `content-` (edits in the
content stream), `pdfium-` (PDFium's page rewrite) or `tex-` (LaTeX PDFs). Where cases are
meant to be compared, such as the same edit with and without letter spacing, their titles say
so.

## Files

| Path | What it is |
|---|---|
| `cases/<id>.json` | A case: its documents, steps and the expected observations. |
| `documents/<hash>.pdf` | The documents cases open or append, named by the first 12 hex digits of their SHA-256, so cases share them. |
| `contents/<hash>.content` | The decoded content of pages, named the same way, for comparing by eye when an app writes different content. Apps don't need them to run the cases. |
| `INDEX.md` | Every case, what it checks and what it guards against. |
| `licenses/` | The license of DejaVu Sans, which some documents embed (see below). |

The documents were generated by PaperKnife's tests; none comes from elsewhere. Some embed
subsets or complete copies of fonts, as PDFs do: the AMS Computer Modern fonts (SIL Open Font
License), Latin Modern (GUST Font License), CM-Super (GPL with an exception for embedding in
documents) and DejaVu Sans (Bitstream Vera license). Every PaperKnife app ships the first three
and keeps their licenses in its `third_party/` folder; DejaVu Sans's license is in
[`licenses/DejaVu-LICENSE.txt`](licenses/DejaVu-LICENSE.txt), so it travels with every copy of
the corpus.

## Running a case

1. Open the session from the bytes of `document`, with `password` if the case has one.
2. Observe the **initial** state.
3. Do each step in order, then observe its **result** and the **state** after it.
4. Compare every observation with `initial` and each step's `expect`.

### Steps

| `action` | Fields | What to do |
|---|---|---|
| `replaceText` | `page`, `run`, `text`, `contentEditing` | Find the one run on the page whose text is exactly `run`, then replace its text with `text` (an empty `text` deletes it). `contentEditing: false` turns off editing in the content stream for this step only, so the edit goes through PDFium's page rewrite. |
| `replaceObject` | `page`, `object`, `text` | Replace the text of the page object with this index, which needn't be text. |
| `rotatePage` | `page`, `quarterTurns` | Rotate the page clockwise. |
| `deletePage` | `page` | Delete the page. |
| `movePage` | `from`, `to` | Move a page. |
| `appendDocument` | `document`, `password` | Append the pages of the case's attachment of that name (`attachments` maps names to files). |
| `undo`, `redo` | | Undo or redo. |

A step with `maxMilliseconds` must finish within that time; such steps guard against crafted
input that took far too long to read.

### Results

Edits and page commands give the edit result:

| Field | Meaning |
|---|---|
| `status` | `Applied`, `NoChange` or `Rejected`. |
| `rejection` | `None`, `InvalidTarget`, `UnsupportedCharacters`, `EditingRestricted`, `PageNotEditable`, `CollateralChange` or `EngineError`. |
| `message` | The message for the user, exactly. |
| `details`, `warnings` | More messages, exactly and in order. |
| `unsupportedCharacters` | The characters an edit can't use, in order. |
| `run` | The edited run as it is in the committed document (see runs below), or null. |

`undo` and `redo` give `{"done": true}` or `{"done": false}`.

### States

| Field | Meaning |
|---|---|
| `pageCount`, `modified`, `canUndo`, `canRedo` | As the session reports them. |
| `sameAs` | After a step: the earliest state whose file has exactly the same bytes as the current one (0 is the document as opened, `k` the state after step `k`), or null. A refused edit leaves the file as it was; undo restores an earlier file exactly. |
| `appended` | After a step: whether the file's bytes begin with all the bytes of the previous state's file, as an incremental update does. |
| `pages` | Every page, in order. |

For each page:

| Field | Meaning |
|---|---|
| `width`, `height` | The displayed size in points, after the page's rotation. |
| `runs` | The page's text runs, in the order the session gives them. |
| `blockers` | The reasons text on the page can't be edited, exactly. |
| `content` | The SHA-256 (lowercase hex) of the page's decoded content as PaperKnife's own reader gives it: every content stream of the page decoded and followed by one space, in order. Null when PaperKnife's reader doesn't read the file (for example because it is encrypted) or the page (for example because another page draws the same stream). |
| `fonts` | The page's fonts, sorted by resource name (ordinal), or null when PaperKnife's reader doesn't read the file. |

A run has `text`, `object` (the index of its first page object), `objects` (how many it spans),
`font` (the name PDFium reports), `size`, `embedded`, `subset`, `invisible` and `bounds` (left,
bottom, right, top in points).

A font has `name` (its resource name), `subtype`, `baseFont`, `firstChar`, `lastChar`, `widths`,
`encoding`, `toUnicode` (whether it has a ToUnicode map), `flags` (of its descriptor),
`fontFile` (`FontFile`, `FontFile2`, `FontFile3` or null) and `programLength` (the decoded
length of that program, or null). `encoding` is null when the font has none, the name when it is
a name, and otherwise `{"base": <BaseEncoding or null>, "differences": {"<code>": "<glyph>"}}`.

### Comparing

- Objects have the same keys, and arrays the same items in the same order.
- Numbers may differ by up to 0.011: sizes, bounds and page sizes are rounded to 0.01 and widths
  to 0.0001, half away from zero, and different processors may round the last digit differently.
- Everything else, messages included, must be exactly the same.

## Updating the corpus

Add or change cases in `CorpusCases*.cs` in PaperKnife for Windows (one file per area), then
regenerate the corpus:

```powershell
$env:PAPERKNIFE_WRITE_CORPUS = '1'
dotnet test --project tests/PaperKnife.Core.Tests/PaperKnife.Core.Tests.csproj --filter-method '*Corpus_IsUpToDate*'
Remove-Item Env:PAPERKNIFE_WRITE_CORPUS
```

Review the changes to `cases/` like code: a changed expectation means PaperKnife now behaves
differently. Then copy the folder into the other apps with their sync scripts.
